# 0006 契约快照模型与解析边界

- Status: Accepted
- Date: 2026-11-10

## Context

契约分析需要复用当前 WASM 解析依赖，同时避免把上游 AST 或 CLI 错误类型变成本项目的公共 API。Core 模块还可能通过类型索引引用函数签名，因此仅比较原始二进制或索引号无法稳定地表示接口。

## Decision

- 新增独立的 `contract` 领域包，拥有本项目的契约快照、接口条目、比较方向、差异和结果类型。该包不依赖 `cli`、命令层或上游 WASM AST。
- 在 `wasm` 适配层中调用现有解析器，将 Core 模块的 import/export 与其类型解析为 `contract` 类型；上游类型只在适配层内出现。命令层负责 IO 与参数，并组合提取和比较 API。
- MVP 的外部契约包括：导入/导出的名称与种类，以及本版本支持的函数、table、memory、global、tag 类型信息。函数签名按结构表达，不将类型段的数值索引作为稳定身份。
- 接口身份由 WASM 外部名称和种类构成：导入使用 `(module, name, kind)`，导出使用 `(name, kind)`。重复或无法无歧义映射的条目必须被保留并显式诊断，不可静默覆盖。
- 契约快照不包含函数体、调用图、调试符号、任意 custom section 或优化结果；这些内容不构成 MVP 的公开接口。
- 对当前无法准确建模的类型或特性，快照记录不支持状态及原因；后续比较产出 `unknown`，不得静默忽略或推断兼容。
- `wasm-gc` 属于 MVP 输入目标，但遇到未支持的 GC/递归类型结构时遵守 `unknown` 规则。完整 GC 类型兼容语义不作为首版承诺。
- Component 二进制与 WIT package/world 模型不进入此版本的数据模型，待 Core MVP 稳定后另行评估。

## Consequences

- 需要为快照设计可版本化的领域类型，并在解析失败、重复名字和未支持类型之间区分诊断。
- `contract` 包可由其他 MoonBit 项目直接构造或消费快照并运行比较；若调用方需要从二进制提取，则使用 `wasm` 适配 API。
- 新增导入/导出种类或支持新的 GC 类型时，需补充规范化与兼容性测试，而非暴露上游 AST 类型。

## Verification

- 对同一接口但类型段索引不同的模块，提取出的结构化契约相同。
- 契约 API 编译时不依赖 CLI 类型和 `wasm_core` 类型。
- 对重复标识、无效类型索引、截断输入和未支持类型均产生确定诊断，不崩溃、不丢失条目。
