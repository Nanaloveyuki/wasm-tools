# 0005 将产品主线转向 WASM 契约兼容性检查

- Status: Accepted
- Date: 2026-11-10
- Supersedes: 0001（仅产品定位与未来范围；原有命令约定仍有效）及 0004 中未交付的未来路线。

## Context

当前项目把自身定位为通用 WASM 二进制工具箱。核心解析、验证、WAT 编解码和优化能力主要来自上游包或 MoonBit 工具链；项目自研的 `size` 与 `symbolize` 提供了一些增量，但不足以支撑“通用工具链”的广泛承诺。评审反馈也指出了这一差距。

项目需要一个能由 MoonBit 开发者直接复用、具备清晰问题边界且主要技术逻辑由本项目实现的主能力。MoonBit 包发布者会遇到一个具体问题：升级生成的 WASM 产物时，如何确认导入/导出接口没有意外破坏既有使用方。

## Decision

- 将“MoonBit WASM 契约快照与兼容性分析”设为下一阶段的产品主线，交付可复用的 MoonBit 分析 API 和 `wsm contract` 命令。解析器只提供输入结构；契约规范化、比较与兼容性结论由本项目实现。
- MVP 面向 MoonBit 编译产生的 Core WASM 模块，包括 `wasm` 与 `wasm-gc` 目标。先覆盖导入/导出契约；Component/WIT 放入后续阶段，不以其完成作为 MVP 验收条件。
- 现有 `validate`、`parse`、`print`、`dump`、`size` 等命令保留为辅助能力，不再作为项目价值主张的中心。暂不删除现有命令或改变已发布模块坐标 `Nanaloveyuki/wasm-tools`。
- 在契约 MVP 交付前，暂停 `compose` 及其他通用工具链扩张，避免同时维护多个尚未验证的主线。
- 新主能力实现可用后，再同步更新 README、模块描述和示例，使项目定位与实际交付一致；在功能尚未落地前，不提前宣称已经具备 ABI 检查能力。
- 已将 0001 标为部分 superseded、0004 标为 superseded，并保留其中已交付能力的设计记录。
- 不实现新的 WASM 二进制解析器、验证器、优化器或运行时；不把既有工具拼接数量当作核心贡献。

## Consequences

- 项目需要新增契约模型、结构化快照、方向性兼容规则、稳定报告和相应测试。
- `wasm_core` 可继续用于解析，但上游对象不得成为契约 API 的公开类型。
- 项目规模通过完整、可测试的契约分析能力自然增长；不以增加无关子命令或行数作为目标。
- Component/WIT 兼容性是潜在的后续扩展，需在 MVP 之后依据真实用例另行确定规则。

## Verification

- 用户能用一个 MoonBit `wasm` 或 `wasm-gc` 产物生成基线快照，并在另一个产物上运行兼容性检查。
- 对照测试能证明接口删除、签名改变和依赖增加会给出有解释的结果；无关 section 顺序和非接口内容不会制造差异。
- 仓库公开一个可运行的 CI 示例，且契约比较 API 可独立于 CLI 使用。
